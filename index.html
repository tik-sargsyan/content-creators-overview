1 repo, shared read-only 0 API keys, ever 2 tracks: Flow + Presets Your account, your credits
01 · The goal

Give every creator a guided path from zero to finished AI content

Artistic creators shouldn't have to wrestle with tokens, keys, or infrastructure. This repo hands them a clear, guided kit: install once, sign in with Picsart, and start making films, ads, cartoons, product visuals, and avatars. Everyone clones the same repo read-only; only the owner changes the code, so the whole team stays in sync and safe.

What it enables

High-value output, no engineering

Creators produce real deliverables (a scored short film, a launch ad, a cartoon short, a product catalog, a stylized avatar) by asking Claude in plain language. The repo supplies the strategy, the ready-made blueprints, and the guardrails; the creator supplies the idea and the taste.

The one rule

  • Everything runs through Picsart sign-in, on the creator's own credits.
  • Every render shows an approval first; nothing spends without an OK.
  • No secrets in the repo. If a step ever asks for an API key, something is wrong.
  • The private internal engine stays completely separate and unseen.
02 · The shared engine

What every creator gets, on both tracks

A common foundation sits under both ways of creating. It handles onboarding, keeps spend and output visible, and enforces the safety model, so the creator only thinks about making things.

Onboarding

creator-setup skill

A guided, one-step-at-a-time setup that detects your OS, installs everything, signs you in, and runs a smoke test. Re-runnable any time as "verify my setup".

Visibility

Tracking & budget

Every create, render, and publish writes to a local ledger. A budget guard reads your live Picsart balance and warns before a big spend. Alert-only, it never blocks you.

Safety

Guardrails, not gates

No API keys, approval on every render, a secret-scan on the repo, and optional quality checks. Local logs and caches keep everything auditable.

03 · The two tracks

Two ways to create, matched to the job

Flow is for connected, multi-piece work with one clear outcome. Presets are for a single quick result. Same sign-in, same credits, same repo.

Track A · Flow

Complex, multi-node workflows

A pipeline of nodes that generate, refine, and assemble a finished piece. One clear outcome per workflow, built on the Picsart Flow canvas from ready-made blueprints.

  • Children's Content & CartoonsPhoto-to-cartoon, characters, storylines, YouTube packaging
  • Filmmaking & StorytellingStory + scene builder, motion, titles, subtitles, shorts
  • Marketing & Content CreationAI video ads, UGC, product launches, repurposing
  • E-commerce & Brand GrowthProduct photography, try-on, videos, listings, catalogs
  • Design & Creative ProductionEditing, background removal, enhancement, brand identity

Ready blueprints: Short Film, Product Ad, Kids Cartoon, Brand-in-a-Box, Creator UGC Trend Kit, each a connected multi-input / multi-output design with a live prod example.

Track B · GenAI Presets

Simple, one-shot content

One input, one preset, one output. Start from a ready recipe and swap in your own subject. Fast, forgiving, and perfect for volume.

  • Portraits & AvatarsPet-to-hero avatar, selfie-to-stylized portrait
  • Photo EditingSelfie-to-pro-photoshoot, restore, relight
  • Products & E-commerceProduct-to-clean-catalog-shot
  • Stickers & IllustrationsPrompt-to-sticker-sheet, icons
  • FashionOutfit-to-editorial-lookbook
  • Branding & LogosSketch-to-clean-logo

Six simple lanes, each with example recipes to copy and adapt.

How to choose: one asset in one step goes to Preset. A story or campaign with several connected pieces, or the same subject across many outputs, goes to Flow.

05 · Setup

From zero to first render in about 5 minutes

The creator-setup skill runs this for the creator, one step at a time, and verifies each before moving on.

Install Claude Code

Desktop app (simplest), the VS Code extension, or the CLI.

Add the Picsart Flow plugin

Marketplace add, then install. It brings the Flow tools and the build skills.

Sign in with Picsart

Your own account, this is where your credits come from. Renders always ask first.

Install ffmpeg + clone the repo

Light local helpers, plus a guided SSH-to-GitLab clone. Access is granted on request.

Configure

Copy the example settings, set your creator name and a monthly credit alert.

Smoke test

Build a tiny Text to Image Flow, approve it, render, and confirm the output. You're ready.

Stuck later? "verify my setup" re-checks everything. "Needs authentication" just means re-run the Picsart sign-in.

06 · Access model

Shared read, single writer, private engine kept apart

Creators

Read-only clone

Every creator gets Reporter access: clone and use the kit, run everything on their own account. They never edit the shared code.

Owner

Single source of truth

Only the owner changes the repo. One update propagates to everyone, so strategy, blueprints, and guardrails stay consistent.

Boundary

The private engine stays hidden

Internal generation IP, competitor analysis, colleague data, and API keys live in a separate private system. This repo reveals none of it.
